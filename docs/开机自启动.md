# 开机自启动

设置页的“开机自启动”在点击后立即写入系统，不依赖中转服务器设置的“保存”。首次使用不会主动注册。登录系统后使用 `--autostart` 在托盘后台运行，主窗口初始隐藏；手动启动显示窗口，关闭窗口仍保留后台同步。

## 实现

- `apps/desktop/src-tauri/src/autostart.rs`：Tauri 2 原生命令，后台执行系统读写；写入后再次读取确认，错误直接显示到设置页。不保存 UI 布尔值到 settings.json。
- macOS：当前用户的 `~/Library/LaunchAgents/com.easycopy.desktop.plist`，`RunAtLoad`、`Aqua` 会话和应用标识；使用 plist 库正确转义路径，临时文件完成写入后原子替换。读取内容核对当前可执行文件及参数，并读取 `launchctl print-disabled` 的系统覆盖状态。兼容项目既有 macOS 12 最低版本。
- Windows：当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `com.easycopy.desktop` 项，命令为 `"实际安装位置\EasyCopy.exe" --autostart`。完整引用带空格/中文的路径；读取对应 `StartupApproved\Run` 状态。用户明确开启时恢复此应用的启用状态，关闭时删除 Run 项；不写全局 HKLM，不需管理员权限。
- 主窗口使用 Tauri 2 单实例插件，先于其他插件初始化。普通重复启动显示并恢复已有窗口；带 `--autostart` 的重复启动只退出新进程。
- UI 每次进入设置页和窗口重新获得焦点时读取系统；更新过程中禁用开关。失败后重新读取，避免系统部分写入后界面仍假设已回滚。读取失败显示错误和重试入口。

采用平台原生注册代码而非直接使用 autostart 插件，是为了校验实际启动命令、正确引用 Windows 安装路径，以及避免将 Mac plist 存在直接视为有效启用。单实例沿用官方插件。

## 正式打包与安装

- 正式构建：在 `apps/desktop` 中运行 `npm run tauri -- build -- --locked`；Mac 默认生成 app，Windows 按现有 `tauri.windows.conf.json` 生成 NSIS 安装包。Mac 发布仍需按发布流程完成签名/公证。
- 将 Mac app 安装到固定位置（建议“应用程序”），或用 Windows 安装包安装后，再从安装位置运行并开启。注册使用运行时的可执行文件位置，不包含仓库路径或构建机路径，不启动脚本、Vite 或 shell。
- 开发、Debug 构建以及 `target`、`.local`、App Translocation / 挂载镜像内的 Mac 程序禁止开启，设置页显示原因；日常启动脚本现默认构建 Release，但仓库构建目录仍禁止注册；显式 Debug 构建同样不可开启。关闭已有有效项仍允许。
- 若手工移动安装目录，旧注册不会被视为当前安装已启用；从新位置重新开启即可更新。正常原位覆盖更新不改变注册路径。
- 卸载前关闭开关，避免遗留指向已删除程序的注册项；本次没有新增卸载钩子，也没有改变现有安装脚本。

平台依据：[Apple launchd 配置](https://github.com/apple-oss-distributions/launchd/blob/main/man/launchd.plist.5)、[Windows Run 注册项](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)、[Tauri 单实例](https://v2.tauri.app/plugin/single-instance/)。

- 浏览器模拟接口覆盖默认无注册写入、开启/关闭参数、写入失败后的回读、外部状态变化刷新、读取失败重试、开发版本限制；1000×700 和 760×540 下布局已查看。入口 `tests/browser-qa.mjs`，可用 `QA_OUTPUT` 避免覆盖原有截图。模拟接口测试不代表真实系统注册已通过。
- `bash script/windows_autostart_check.sh` 对真实 Windows 后端及其测试代码完成交叉类型检查；不是完整 Windows 客户端构建或 Windows 实机测试。
- 使用原有 `./script/build_and_run.sh --verify` 完成 Debug app 构建、Apple Development 完整签名及校验、实际启动。原生设置页显示关闭状态与开发版限制，已有服务器连接正常。分别带登录参数与普通参数重复打开后均只保留原进程；没有开启系统自启动。
- Release 构建暴露现有 `strip = true` 导致编译期宏库无法加载的问题（`E0463`）；通过 `dlopen` 确认具体为 `mis-aligned LINKEDIT string pool`。根 Cargo 配置增加 `[profile.release.build-override] strip = false`，仅编译期依赖不裁剪，最终程序仍按原配置裁剪。配置依据：[Cargo 构建期依赖覆盖](https://doc.rust-lang.org/cargo/reference/profiles.html#build-dependencies)。
- 修复后 Tauri Release `.app` 打包成功（14.89 MiB）。本轮使用独立输出目录 `apps/.local/autostart-release-target`，避免干扰并行性能评估的构建；该验证包未安装到应用程序目录、未分发。日志在 `.local/autostart-release-build-fixed.log`，Rust 测试在 `.local/autostart-tests.log`，界面证据在 `.local/autostart-browser-qa/`（均为忽略的本地验证产物）。

### 安装后的实机验收

1. Mac 正式 app / Windows NSIS 安装后首次进入设置，确认默认关闭，系统不存在本应用启动项。
2. 开启后检查真实 plist / Run 项中的路径指向安装目录，带 `--autostart`；关闭退出再打开应用，状态与系统一致。Windows 包括带空格和中文的安装路径。
3. 用户自行注销再登录或重启：开启时仅一个后台进程、有托盘、无主窗口；托盘“打开 EasyCopy”显示窗口，已有配置正常连接。关闭后再次登录不启动。代理未为此注销或重启电脑。
4. 已运行时普通重复启动只显示已有窗口，登录参数重复启动不抢焦点；退出后可以重新启动。
5. 在系统登录项/启动应用设置中禁用后，回到应用检查状态；macOS 新版“允许在后台”策略、企业设备管理限制仍需实机验证，不能把 plist/launchctl 校验等同于已绕过全部系统策略。
6. 模拟注册写入权限拒绝，确认报错、回读真实状态；覆盖升级保持有效路径，移动位置后重新开启更新路径。验证卸载前关闭后不再留下自启动项。

本次不改变用户真实自启动状态，不涉及中转服务器部署或性能优化。
