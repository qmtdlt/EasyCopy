# EasyCopy 中转服务

## 运行与配对

开发运行：`cargo run -p easycopy-relay -- serve --data-dir .local/relay --bind 127.0.0.1:8443`。

在可信终端执行 `cargo run -p easycopy-relay -- pairing --data-dir .local/relay`，把输出整串填入客户端“连接密钥”。正常服务日志不输出连接密钥、secret 或私钥。地址填实际 IP，端口默认 8443；客户端使用配对串的稳定逻辑名完成证书验证。

Linux Compose：在项目根目录执行 `docker compose -f deploy/compose.yaml up -d --build`；随后通过 SSH 到服务器，执行 `docker compose -f deploy/compose.yaml exec -T relay easycopy-relay pairing` 取得配对串。`docker compose -f deploy/compose.yaml ps` 查看 TLS + 鉴权自检结果。`192.168.1.48` 使用无需镜像仓库的离线部署路径，实际步骤与验证结果见 [Ubuntu 部署记录](Ubuntu部署记录.md)。

完整迁移必须保留 `relay-data` 卷，尤其 `identity/`。根 CA、服务器证书、私钥与随机认证信息首启生成后持久化；只移动 IP 不需要重新配对。根 CA 有效期约 20 年，服务器证书约 10 年，当前没有自动续期/撤销管理界面。到期前需要维护证书，不会关闭证书校验来绕过错误。

## 存储与协议

- `metadata.sqlite3` 保存记录、服务器顺序与状态；`payloads/{id}.payload` 保存 opaque UTF-8/PNG/TAR。服务端不解包 TAR。
- 登记在 SQLite 事务内分配单调顺序，上传完成顺序不改变复制顺序。id 重复只允许相同登记字段，完整上传重试只允许相同长度和 SHA-256。
- 上传从零写入 `.part`，流式 SHA-256；完成 flush/sync、重命名和状态更新后才发完成事件。失败、取消、连接中断不发布成功。服务重启把遗留 Uploading 标记 Failed 并清理临时文件。
- 上传开始前把所有正在上传的剩余大小计入空间预留；接收每一块前重新检查至少 1 GiB 安全余量。总载荷无固定上限；60 秒无数据判为上传中断。
- WebSocket 先在同一个状态锁内取得最近 10 条记录、全部登记的 high_water 和实时订阅。广播落后时发送 resync_required 并断开。客户端必须据 high_water 拒绝旧任务覆盖当前剪贴板。
- 历史快照只返回最近 10 条，服务端当前保留全部已完成内容及元数据；达到磁盘安全余量后明确拒收。自动服务端保留策略尚未加入，不能手工删除仍在使用的数据文件。

本机测试与 Docker 验证结果由主代理汇总到验收记录；Windows、微信与实际远程 Linux 的结果不得由服务端单元测试替代。
