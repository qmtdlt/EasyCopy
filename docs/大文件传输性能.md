# 大文件传输性能验证

日期：2026-11-04。问题：Mac 复制三百多兆文件到 Windows，用户感受约两分钟，开始和结束尤其慢。

## 改动与边界

- 文件准备复用 `archive::pack` 对完整落盘 TAR 计算的长度与 SHA-256，删除历史快照还原之后的第二次完整扫描。文本、图片的校验保持原样。
- TAR 写入与还原增加 256 KiB 缓冲。缓冲位于 `GuardedWriter` 外侧，每次真正写盘仍检查磁盘余量并保留并发写入预留；明确 flush 后才 sync_all。
- 上传读取块由默认 4 KiB 改为 256 KiB；下载将网络碎片合并为最多 256 KiB 后写盘，并在 Tokio 写入完成前持有空间预留。末尾不足一块的数据也写入并同步。
- 下载进度最多每 50 ms 通知一次，完整长度和 SHA-256 验证成功后保证最后一次进度通知。`flush` 等待异步写入完成，不是每块 fsync；持久化仍由最终 `sync_all` 完成。
- Mac 和 Windows 日常启动脚本默认构建 Release。Mac 保留完整 Apple Development 签名、`com.easycopy.desktop` 标识与局域网用途说明；`--debug` 才构建 Debug，`--acceptance` 保留隔离配置，`--build` 只构建和签名。Windows 用构建标记识别需要升级的旧便携 Debug 版本，显式 `-DebugBuild` 输出到独立目录，避免后续普通启动误用 Debug。
- 保留完整存储转发、服务端验证后发布、历史快照、复制意图顺序、重试、离线规则和私有 CA 校验。不更改协议，不部署到日常 relay，不改用户配置或密钥。

当前仍是先准备并计算一次完整摘要，再上传，因为协议要求请求头携带完整 SHA-256。真正边上传边生成最终摘要，需要另行设计上传结束后的提交/校验协议；本次没有假装实现这一行为。

## 测量方法

基准程序：`crates/integration-tests/examples/transfer_bench.rs`。默认仅启动临时目录、随机回环端口及新身份的 relay，不创建系统剪贴板，不读取用户文件或客户端配置。使用 333 MiB（349175808 字节）确定性非零合成文件，TAR 为 349177344 字节；不压缩，不使用稀疏文件。源文件和两份还原文件均另算 SHA-256 校验相同。

阶段：打包（包括首次 SHA-256）→ 本地历史快照 → 旧实现重复摘要 → 上传并等待服务端校验/落盘响应 → 下载并校验/落盘 → 接收端还原。总耗时是这些阶段之和，**不含**合成数据生成、额外比对、连接建立、复制轮询、意图登记、UI 和原生剪贴板写入。它不是用户点击复制到 Windows 可粘贴的实机时间。

旧版本基于 `24c8245` 的只读导出，基准程序相同；`EASYCOPY_BENCH_LEGACY_PREPARE=1` 在旧基准中模拟 `prepare` 的重复摘要。新程序默认复用 pack 摘要。对照时保留独立可执行文件，避免 Cargo 跨源码目录共用 target 的缓存误用。不要在正在开发的共享工作区切分支做对照。

本机：Apple M3 Pro、18 GiB 内存、macOS。使用文件系统自然缓存，不清空系统缓存。局域网：Mac 路由实际经 **Wi-Fi/en0** 到 Ubuntu `192.168.1.48`。独立 Docker 实例使用本地已有 `easycopy-relay:2026-11-03` 镜像、新匿名数据卷和新配对身份，临时端口 18444；没有使用日常 8443 服务或其身份。上传和下载均由 Mac 基准程序执行，所以 **不是 Mac↔Windows 双机结果**。

## 结果

以下本机数据取最终三轮交替执行的中位数，执行时没有并行编译；早期有编译竞争的探索数据不混入此表。两列都用 Release，隔离出代码改动本身的作用；各阶段和总耗时分别取中位数，不要求逐格相加恰好等于总计。

| 本机回环阶段，333 MiB | 旧代码 Release | 优化后 Release |
| --- | ---: | ---: |
| 打包与首次摘要 | 1.081 秒 | 0.917 秒 |
| 本地历史快照 | 0.307 秒 | 0.164 秒 |
| 重复摘要 | 0.759 秒 | 已删除 |
| 上传及服务端校验落盘 | 1.089 秒 | 0.901 秒 |
| 下载及校验落盘 | 0.842 秒 | 0.841 秒 |
| 接收端还原 | 0.317 秒 | 0.197 秒 |
| 总阶段耗时 | **4.387 秒** | **3.023 秒** |
| 下载进度回调 | 841 次 | 17 次 |

同为 Release 的本机阶段耗时减少约 **31%**，下载数据阶段基本持平。收益主要来自删除重复摘要、归档写入/还原缓冲和减少上传读取调度；不能归因为全部网络提速。

另做一轮无并行编译的旧 Debug 基准：打包/首次摘要 **12.533 秒**，历史快照 0.314 秒，重复摘要 **12.229 秒**，模拟准备合计 **25.076 秒**；新 Release 模拟准备约 **1.08 秒**。这包含构建模式和代码优化两种收益，不能全部算作缓冲优化。旧 Debug 全阶段为 50.491 秒，但其本机 relay 也是 Debug，不能当成原先日常 Ubuntu Release 服务的实机耗时。初次伴随编译的 Debug 探索值约 90 秒已排除。

| Mac Wi-Fi ↔ Ubuntu 隔离服务，双方 Release | 旧代码 | 优化后 |
| --- | ---: | ---: |
| 第一轮总阶段耗时 | 70.427 秒 | 68.149 秒 |
| 第二轮总阶段耗时 | 64.107 秒 | 65.729 秒 |
| 两轮上传耗时范围 | 31.475–37.937 秒 | 34.307–36.147 秒 |
| 两轮下载耗时范围 | 29.888–30.058 秒 | 30.149–30.571 秒 |

这组局域网结果**没有证实整体网络阶段有明显改善**，约 65–70 秒主要花在实际传输上。第一轮期间另一个聊天曾进行应用编译，且 Wi-Fi 有自然波动；样本量仅两轮，不能拿约 0.3 秒的总耗时均值差宣称加速。256 KiB 缓冲在本机降低上传和归档开销，但不能代替链路测量或推导千兆速度。

## 复现

```sh
# 优化版，本机临时 TLS relay；默认 333 MiB。可设 EASYCOPY_BENCH_MIB=32 快速检查。
cargo run --locked --release -p easycopy-integration-tests --example transfer_bench

# 只有专门新建的、没有日常客户端的隔离 relay 才能传给这个选项。
# 私有配对文件应为 0600；不得使用日常服务密钥，也不得写进日志。
cargo run --locked --release -p easycopy-integration-tests --example transfer_bench -- \
  --isolated-relay HOST PORT PRIVATE_PAIRING_FILE
```

基准没有默认联网到局域网的行为。远程测试完应删除独立容器及匿名卷、删除本地临时配对文件。原始测量记录只保留耗时、大小、是否校验成功，不包含密钥或用户内容。

## 回归与实机验收

核心、协议、relay 和集成测试覆盖身份校验、复制意图顺序、离线快照及长时间上传；新增下载测试覆盖空文件、小文件、整块、跨块尾部、错误摘要、长度不符和禁止覆盖。归档新增测试覆盖跨块文件摘要及源文件变化后的历史快照。原生剪贴板探针保持忽略。

已执行：核心/协议/relay/集成回归共 31 项通过；补充归档快照测试后重跑核心，17 项通过（合计 32 项不同测试通过）。`rustfmt --check`、`git diff --check`、Shell 语法检查通过。Windows PowerShell 构建脚本仅静态检查，未在 Windows 执行。

Mac 使用已完成的自启动任务构建目录复用依赖：

```sh
CARGO_TARGET_DIR="$PWD/apps/.local/autostart-release-target" ./script/build_and_run.sh --verify
```

前端与 Release 构建、整包签名校验、启动进程检查均通过；原生应用界面显示“已连接”。当前运行包位于 `apps/.local/autostart-release-target/release/bundle/macos/EasyCopy.app`，常规不指定 `CARGO_TARGET_DIR` 时仍使用 `target/release/bundle/macos/EasyCopy.app`。保留另一聊天修复的 Release 编译期宏库裁剪例外，没有覆盖其自启动修改。没有触发真实剪贴板压测。

临时 `easycopy-perf-20261104` 容器及匿名卷已自动删除，本地临时配对文件已删除，日常 8443 relay 和其他容器仍运行。没有提交、推送或更新日常服务镜像。

Windows 的完整构建、真实复制粘贴和大文件耗时需要在 Windows 实机验收：两端使用 Release，复制受控合成文件，分别记录准备、上传、下载/校验、可粘贴时刻；再校验接收文件摘要。不能把 Mac 本机基准或 Mac↔Ubuntu 测量标为 Windows 通过。

Windows 更新入口：先退出系统托盘里的 EasyCopy，再执行 `.\Start-EasyCopy.cmd -Build`。它保留普通配置、历史和系统凭据，不需要重新生成配对密钥。
